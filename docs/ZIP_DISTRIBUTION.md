# Download archive compatibility

The compatibility boundary contains 107 already-published asset/version pairs
and 12 frozen v1.4.0 publication candidates, all generated with ZIP STORE.
The pending candidates are preserved even before publication is confirmed. `scripts/lib/legacy-store-packages.json` freezes those exact
`id@version` pairs. Keep the list unchanged: existing versioned URLs and saved
release catalogs must continue to resolve to their original archive bytes.

Packages outside that compatibility list use raw DEFLATE at level 6, but retain
STORE for any entry that would not become smaller. This applies to both full
and models-only archives, without changing their filenames or member lists.
Raw downloads, previews, attribution, licenses, source bytes, and catalog schema
are unchanged. Models-only archives still retain all source dependencies and
omit presentation files. Generated byte counts and SHA-256 values describe the
actual ZIP bytes.

The ZIP validator accepts both methods and checks local/central header agreement,
expanded sizes, CRCs, archive membership, source hashes, and attribution. Tests
cover the frozen compatibility policy, a legacy archive fixture, deterministic
compression within one runtime, STORE fallback, and corruption detection.

## Canonical runtime and fail-closed archive ledger

New compressed packages require the official Node **22.23.3** Linux x64 runtime,
with zlib **1.3.1-e00f703**. `.node-version`, the workflow and
`scripts/lib/archive-runtime.json` pin this profile; generation checks it before
clearing generated output, and the compression writer checks it independently.
The profile explicitly fixes raw DEFLATE level 6, strategy 0, windowBits 15 and
memLevel 8. There is no environment-variable bypass.

This exact Node version was observed, not inferred, in successful repository
[CI run 38588682287](https://github.com/Xenoah/meshcopia/actions/runs/38588682287),
[verify job 115937436469](https://github.com/Xenoah/meshcopia/actions/runs/38588682287/job/115937436469).
The setup log reports Node 22.23.3 and npm 10.9.9. The zlib version was measured
from the official Linux x64 distribution after verifying its SHA-256 against
the official Node SHASUMS256.txt; the runtime profile records that distribution
URL and hash. CI's Node 24 action runner is separate from this build runtime.

`docs/archive-lock.json` is an append-only regression ledger of versioned ZIP
URLs, sizes, SHA-256 hashes and producer profiles. It initially contains all 202
ZIPs for the 119 compatibility pairs, including the 12 frozen candidates whose
publication was pending at this boundary. A locked candidate is not a claim of
successful publication. Its bytes are nevertheless frozen from then on.

Generation rejects changed or missing locked archives. `npm run check` also
rejects every unsealed new archive before a Pages artifact is uploaded. CI
compares the ledger with all reachable historical revisions, so a multi-commit
delete/re-create cannot erase previous identities. It never updates the ledger.
The initial 119 identities additionally have a fixed regression digest in tests.

For a genuinely new package version, use the pinned runtime to build and run all
checks. The last distribution check will report its unsealed ZIPs. Review the
exact files, attribution and archive contents, then explicitly run
`node scripts/check-archive-lock.mjs --append-new` locally. That command can only
append missing versions after verifying every existing locked hash; it cannot
replace a hash. Review/commit the ledger, then rerun `npm run check`, texture QA
and the unchanged browser gate. Archive sealing alone never authorizes publishing.

Use `node scripts/check-archive-lock.mjs` for a read-only hash check and
`node scripts/check-archive-lock.mjs --check-history` for the append-only check.
The latter requires a complete Git history, as the workflow already fetches.

Changing Node, zlib, compression settings, metadata or source bytes must not
silently alter an existing versioned ZIP. If a guard fails, restore the pinned
runtime/original inputs or restore the exact old ZIP bytes from trusted archived
artifacts; do not regenerate a different ZIP and update its hash. An asset
version update also cannot silently remove the prior URL. The current generator
does not retain old versions automatically, so such an update deliberately
blocks until preservation of those original bytes is explicitly implemented.
The ledger is not a backup: retain the verified publication artifacts.

For a future runtime security update, first preserve every old locked ZIP byte
and introduce a separately reviewed producer profile for never-published
versions. Do not disable the guard or keep an unsafe runtime merely for hashes.
No new deflater dependency is needed for this profile. A pin alone is not the
immutability guarantee; the immutable ledger and blocking checks are essential.

The six infrastructure drafts outside the frozen v1.4.0 candidate catalog were
never-published package versions at this policy boundary and may use DEFLATE.
This policy is independent of draft/public status on subsequent builds and is
not inferred from a changing collection roster, asset prefix, or creation date.
