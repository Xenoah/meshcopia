# 街モデルの導入・再利用チェックリスト

資料確認日: **2026-10-14**。この文書は導入ガイド案であり、公開告知ではありません。
まず対象素材の `asset.json` と、同じファイルハッシュに対応する検証記録を確認してください。
60モデルの選定版はローカルレビュー済みですが、公開と対象エンジンでの検証は別工程です。
ドラフト、選定リスト、GLBの形式検証、ブラウザ表示だけでUnity／VRChat対応済みとは判断しません。

## ファイルの内容と制限

- **GLB（glTF 2.0バイナリ）**: 見た目を保持する導入に推奨。静的メッシュ、頂点法線、UV、PBR材質を含み、画像がある場合は埋め込みます。この街モデル群は **メートル・Y-up**。`dimensions` は `[X, Y, Z]` の外接寸法で、施工用の公称寸法ではありません。glTFは右手座標系なので、対象エンジンへの座標変換はインポーターに任せます。[glTF仕様](https://registry.khronos.org/glTF/specs/2.0/glTF-2.0.pdf)
- **バイナリSTL**: 形状のみの代替形式。座標値はメートル・Y-upで作成していますが、STLには単位・軸を確実に伝える標準メタデータがありません。読み込み時に倍率・軸を明示し、寸法を照合してください。無条件にミリメートル変換しないでください。配布STLには色、材質スロット、UV、画像、階層、滑らかな頂点法線シェーディングはありません。Blenderでは倍率・シーン単位・軸の設定を確認できます。[BlenderのSTL設定](https://docs.blender.org/manual/id/4.5/files/import_export/stl.html)
- 全体の原点は水平方向の中央、最下点は `Y=0` です。これは**配置用原点**で、壁の取付基準面、蝶番、車軸、チェーンの関節などの動作支点ではありません。壁・屋根設備は用途に応じた高さへ配置し、必要なら取付・回転用の親オブジェクトを作成します。
- すべて静的・未リギングの可視化用素材です。コライダー、LOD、風、ナビゲーション、機器の動作は付属しません。発光面は実行時ライトではなく、扉・車輪・スイッチの名前も可動機構を保証しません。交差する部品や開いた面は意図的な場合があります。STL付属は、水密性、3Dプリント適性、製造・構造・医療・安全基準への適合を意味しません。

## MCP／自動化エージェント向け導入手順

1. **対象を確定する。** 素材ID・版、GLB／STLのSHA-256、ライセンス、出典、寸法を記録します。承認されたマニフェストのファイルを使い、同名の中間ファイルで置き換えません。`asset.json`、作者表示、ライセンス通知を保持します。
2. **変更前に導入先を調べる。** エディター版、インポーター名・版、レンダーパイプライン、ビルド対象を記録します。GLB／STLの標準インポーターがあるとは限りません。Unity 2022.3の標準モデル形式一覧はFBX／DAE／DXF／OBJで、GLB／STLは含まれません。[Unityのモデル形式](https://docs.unity3d.com/2022.3/Documentation/Manual/3D-formats.html)
3. **対応した経路を一つ選ぶ。** 互換性のあるUnityプロジェクトでは、公式パッケージ `com.unity.cloud.gltfast` がGLBをEditorで読み込み、UnityのPrefabに変換します。6.14文書の6.x移行案内は **Unity 2021.3.46f1以降**を条件としていますが、採用するパッケージ版の要件・依存関係を実プロジェクトで確認してください。複数の既定GLBインポーターを競合させないでください。この文書は導入済み・動作確認済みの環境を示すものではありません。[導入方法](https://docs.unity3d.com/Packages/com.unity.cloud.gltfast@6.14/manual/installation.html)、[版の条件](https://docs.unity3d.com/Packages/com.unity.cloud.gltfast@6.14/manual/UpgradeGuides.html#upgrade-to-60)、[Editorでの読み込み](https://docs.unity3d.com/Packages/com.unity.cloud.gltfast@6.14/manual/ImportEditor.html)
   - 別経路として、BlenderでGLBを読み込み、別名のFBXへ書き出せます。変換後に法線・倍率・画像・材質を再確認します。拡張子の変更だけでは変換できません。見た目を残す変換でSTLを経由しないでください。[BlenderのglTF入出力](https://docs.blender.org/manual/es/4.5/addons/import_export/scene_gltf2.html)
4. **一括導入の前に一体を確認する。** 外接寸法・接地位置をメタデータと照合し、前後・斜光で確認してから、元ファイルを上書きせずプロジェクト側のPrefabを保存します。法線、ハードエッジ、UV境界、材質割当、透過モード、両面設定を保持します。正常な素材を「最適化」するために、無条件で頂点を結合したり法線を再計算したりしないでください。
5. **材質ごとの差を確認する。** 大半は画像テクスチャではなく定数色のPBR材質です。ガラス・表示面などの `BLEND` 材質は、対象パイプラインで描画順・深度・影・裏面を確認します。街路樹では、埋め込み樹皮色／法線マップ、タンジェント、葉の `COLOR_0` 頂点色、薄い葉の両面設定を保持します。法線マップは色画像ではなく接空間のデータで、glTFは+Y規約です。緑チャンネルを無条件に反転せず変換結果を確認します。画像のサンプリング設定と材質係数を保持し、未収録のマップがあるとは説明しません。[BlenderのglTF材質](https://docs.blender.org/manual/es/4.5/addons/import_export/scene_gltf2.html#materials)
6. **用途別データを追加する。** UV0は部品間で重複し、固有に展開されたライトマップUV2ではありません。ベイクする場合は、余白があり重複しない第2UVを作成・検証します。UnityのModel Importerには生成機能がありますが、GLBのScriptedImporterでは設定が異なる場合があります。衝突判定・LOD・操作機能は別途用意します。[UnityのライトマップUV](https://docs.unity3d.com/2022.3/Documentation/Manual/LightingGiUvs-GeneratingLightmappingUVs.html)
7. **実際の利用先で検証する。** Editorのエラーだけでなく、採用シェーダーを使ったビルドも確認します。実行時にglTFを読み込む方式では、必要なシェーダーバリアントの収録も確認します。グループ化で減るノード／プリミティブ数は、三角形数、実際のドローコール数、フレーム時間とは別です。性能を約束する前に、対象端末で描画カウンターとCPU／GPU時間を測定してください。[glTFastのプロジェクト設定](https://docs.unity3d.com/Packages/com.unity.cloud.gltfast@6.14/manual/ProjectSetup.html)、[Unity Rendering Profiler](https://docs.unity3d.com/2022.3/Documentation/Manual/ProfilerRendering.html)

**VRChatで使う場合**は、Creator Companionと、その時点で対応する制作環境のUnity版を使用します。
2026-10-14に確認した公式案内は **2022.3.22f1** です。設定時に再確認し、インポーターのために新しいUnityメジャー版へ変更しないでください。
Editor側での読み込み・変換を基本とし、シェーダー、SDKビルド、実際の対象プラットフォームで検証します。
この素材群にはVRChat SDK／実行時の連携機能は付属せず、動作検証もしていません。[VRChatの対応Unity版](https://creators.vrchat.com/sdk/upgrade/current-unity-version/)

## 再生成・権利・検証結果の記録

- 再生成は `usages[].sourcePaths` と対象セレクター、生成・後処理コードの版、Blender版、記録がある場合は乱数シードを確認し、別の作業ディレクトリで行います。Blender 4.3.2と4.5.14由来の素材が混在するため、一つのコマンド・版ですべての最終出力を再現できるとは限りません。移動する `main` のURLは固定リビジョンではありません。
- グループ化版は、元データと出力の三角形各頂点の位置・法線・UV・材質レコードを照合します。PBR材質と画像を保持し、三角形数の一致だけで見た目の同等性を判断しません。再生成物でレビュー済み配布物を置き換える前に、ハッシュ・形状・見た目を再検証します。
